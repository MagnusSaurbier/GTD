# GTD App — Architecture and frozen contracts

Read this before any task. `docs/REQUIREMENTS.md` says *what*; this file says *how* and
fixes the seams between parallel tasks. Requirement IDs (N1, I4, P5 …) refer to REQUIREMENTS.md.

If a contract here turns out wrong, do **not** silently diverge: make the smallest change,
and record it under "Contract changes" in your task doc so the orchestrator can broadcast it.

## 1. Stack

- Swift 6 (strict concurrency), SwiftUI, Observation (`@Observable`). Minimum iOS 18 / macOS 15.
- One multiplatform app target (`GTD`) generated by **XcodeGen** from `project.yml`
  (`.xcodeproj` is git-ignored; agents never edit a pbxproj).
- All code lives in one local Swift package, `Packages/GTDKit`, split into many small targets.
  The app target is a thin shell. Everything non-UI must build and test with plain
  `swift build` / `swift test` on macOS.
- Only third-party dependency: [Yams](https://github.com/jpsim/Yams). Anything else needs a note in the task doc.
- No database. The vault's markdown files are the single source of truth; the app keeps an
  in-memory `VaultSnapshot` rebuilt from files.


Features depend on `GTDAppCore` + `GTDDesign` only — never on `GTDVault`/`GTDServices`.
They are developed against `InMemoryBackend` + `GTDFixtures` and SwiftUI previews.

## 3. Vault layout

All paths are relative to the vault root the user picks (the folder containing `Actions/`).
Defaults live in `VaultLayout` and are overridable in config.

| Path | Content |
| --- | --- |
| `Inbox/<yyyy-MM-dd HHmmss>[-n].md` | one capture per file (C3). Frontmatter: `created`, optional `reviewReason` |
| `Actions/<Title>.md` | one note per action (A1) |
| `Archive/YYYY/MM/` | done actions older than 30 days (A5) |
| `Projects/<Area>/<Area>.md` | area note, frontmatter `kind: area` |
| `Projects/[<Area>/]<Project>/<Project>.md` | project note, frontmatter `kind: project`, `status` |
| `Knowledge/**` | free folder tree (I4) |
| `GTD/Config.md` | synced settings in frontmatter (contexts, on-the-go set, cap, routine times) |
| `GTD/Routines/<Name>.md` | routine templates (R1) |
| `GTD/RoutineLog/<yyyy-MM-dd>--<deviceID>.md` | routine log, one file per day **per device** (R5, N3) |
| `GTD/Reviews/<yyyy>/KW <ww>.md` | weekly review notes (§10.4) |
| `GTD/Trash/` | trashed inbox items. The app never hard-deletes a vault file. |

Device-local state (bookmark, undo journal, resumable review wizard state, notification
bookkeeping) lives in Application Support, **not** in the vault.

### Note formats

Action (A1, schema in REQUIREMENTS §5):

```markdown
---
status: next
contexts: [mac]
timeEstimate: 30
project: "[[Projects/Applications/DAAD/DAAD]]"
created: 2026-09-18T21:04:11+02:00
---
# Why?
…
# What?
- [ ] …
```

Project note (P2): frontmatter `kind: project`, `status`; body sections `# Outcome`, `# Why?`,
`# Steps` (checkbox list; a promoted step becomes `- [ ] text → [[Action title]]`),
`# Log` (`- 2026-09-18 Did X`).

Routine template (R1): frontmatter `time: "07:00"`; body is a checkbox list, one top-level
item per step, nested items are sub-steps. Step id = slug of the step text. Frontmatter
`journalSteps` is not needed — all steps are done/skip only (R4).

Routine log: frontmatter `entries:` list of `{routine, step, result: done|skipped, at}`.

**Round-trip rule (N2):** the codec must preserve unknown frontmatter keys, key order where
feasible, and unknown body sections byte-for-byte. Empty means absent or empty — never a
fake default (`timeEstimate: 0` is forbidden, §1 "no lying defaults").

## 4. Frozen contracts (Swift)

T00 turns these into compiling code. Signatures are normative; bodies are up to the owner.

### GTDModel

```swift
public struct NoteID: Hashable, Sendable, Codable { public let path: String }   // vault-relative, "/"-separated
public struct Day: Hashable, Comparable, Sendable, Codable { public let year, month, day: Int } // no time zone bugs

public enum ActionStatus: String, Sendable, CaseIterable { case next, backlog, maybe, inProgress = "in-progress", waiting, done, trash }
public enum ProjectStatus: String, Sendable, CaseIterable { case active, onHold = "on-hold", someday, done }
public enum TimeBucket: Sendable, CaseIterable { case upTo10, upTo30, upTo60, over60   // chips write 10/30/60/90
  public init?(minutes: Int?); public var minutes: Int }

public struct NotePassthrough: Sendable, Equatable { /* opaque; filled and read only by GTDMarkdown */ }
public struct Checkbox: Sendable, Equatable { public var text: String; public var done: Bool }

public struct InboxItem: Identifiable, Sendable, Equatable {
  public let id: NoteID; public var text: String; public var created: Date
  public var reviewReason: String?            // non-nil ⇒ deferred to weekly review (I5), excluded from the queue
  public var passthrough: NotePassthrough }

public struct Action: Identifiable, Sendable, Equatable {
  public let id: NoteID; public var title: String          // filename stem
  public var status: ActionStatus
  public var contexts: [String]; public var timeEstimate: Int?
  public var project: NoteID?; public var deferDate: Day?; public var due: Day?
  public var waitingFor: String?; public var followUpDate: Day?
  public var created: Date?; public var completedDate: Date?; public var reviewReason: String?
  public var modified: Date?                                // file modification date, read-only, set by GTDVault (staleness stats)
  public var why: String; public var what: String           // markdown
  public var checkboxes: [Checkbox] { get }                 // parsed from `what`
  public var passthrough: NotePassthrough }

public struct Area: Identifiable, Sendable, Equatable { public let id: NoteID; public var title: String }
public struct ProjectStep: Sendable, Equatable { public var text: String; public var done: Bool; public var promotedTo: NoteID? }
public struct LogEntry: Sendable, Equatable { public var day: Day; public var text: String }
public struct Project: Identifiable, Sendable, Equatable {
  public let id: NoteID; public var title: String; public var area: NoteID?
  public var status: ProjectStatus; public var outcome: String; public var why: String
  public var steps: [ProjectStep]; public var log: [LogEntry]
  public var referenceFiles: [String]                       // other files in the project folder (P6)
  public var passthrough: NotePassthrough }

public struct RoutineStep: Identifiable, Sendable, Equatable { public let id: String; public var title: String; public var substeps: [String] }
public struct Routine: Identifiable, Sendable, Equatable { public let id: NoteID; public var title: String; public var time: DayTime?; public var steps: [RoutineStep] }
public enum RoutineStepResult: String, Sendable { case done, skipped }
public struct RoutineLogEntry: Sendable, Equatable { public var day: Day; public var routine: String; public var step: String; public var result: RoutineStepResult; public var at: Date; public var device: String }

public struct GTDConfig: Sendable, Equatable {
  public var contexts: [String]            // default: mac phone home campus errands calls reading deep-work
  public var onTheGoContexts: [String]     // default: phone errands calls reading
  public var nextCap: Int                  // 15
  public var layout: VaultLayout }

public struct VaultIssue: Sendable, Equatable { public var path: String; public var message: String }   // unparsable file, conflict copy …

public struct VaultSnapshot: Sendable, Equatable {
  public var inbox: [InboxItem]; public var actions: [Action]        // excludes Archive/
  public var areas: [Area]; public var projects: [Project]
  public var routines: [Routine]; public var routineLog: [RoutineLogEntry]   // last 14 days, all devices
  public var knowledgeFolders: [String]; public var config: GTDConfig
  public var lastReview: WeeklyReview?                       // most recent KW note (shown alongside in §10.4)
  public var issues: [VaultIssue] }
```

Drafts and commands — every mutation in the app is one `GTDCommand`:

```swift
public struct WaitingInfo: Sendable, Equatable { public var who: String; public var followUp: Day }
public struct ActionDraft: Sendable, Equatable { title, status, contexts, timeEstimate, project, deferDate, due, waiting: WaitingInfo?, why, what }
public struct ProjectDraft: Sendable, Equatable { title, area: NoteID?, newAreaTitle: String?, outcome, why, steps: [String] }

public enum InboxDecision: Sendable {
  case action(ActionDraft)                                   // next / backlog / maybe / waiting
  case knowledge(folder: String, title: String)
  case newProject(ProjectDraft, firstActions: [ActionDraft])
  case existingProject(NoteID, actions: [ActionDraft])
  case trash }

public enum GTDCommand: Sendable {
  case editInboxText(NoteID, String)
  case fileInbox(NoteID, InboxDecision)
  case deferInboxToReview(NoteID, reason: String)
  case createAction(ActionDraft)
  case updateAction(Action)
  case setStatus(NoteID, ActionStatus, waiting: WaitingInfo?)
  case complete(NoteID)
  case toggleCheckbox(NoteID, index: Int)
  case convertActionToProject(NoteID, ProjectDraft)
  case createArea(title: String)
  case createProject(ProjectDraft)
  case updateProject(Project)
  case promoteStep(project: NoteID, stepIndex: Int, ActionDraft)
  case saveWeeklyReview(WeeklyReview)
  case logRoutineStep(routine: NoteID, stepID: String, RoutineStepResult)
  case setRoutineTime(routine: NoteID, DayTime?)
  case updateConfig(GTDConfig)
  case archiveCompleted }

public enum GTDError: Error, Sendable, Equatable {
  case nextCapReached(cap: Int)            // I4, A3 — UI must offer demote-something or Backlog
  case waitingInfoRequired                 // W1
  case notFound(NoteID), titleCollision(String), invalid(String) }

public enum AppPrompt: Sendable, Equatable {
  case whatsNext(project: NoteID)          // P5
  case suggestTurnIntoProject(action: NoteID) }   // A2

public enum VaultFileOp: Sendable, Equatable { case put(path: String, text: String), move(from: String, to: String), delete(path: String) }

public struct ReducerEnv: Sendable { public var now: Date; public var today: Day; public var deviceID: String; public var calendar: Calendar }
public struct Reduction: Sendable { public var snapshot: VaultSnapshot; public var prompts: [AppPrompt]; public var extraOps: [VaultFileOp] }
public enum Reducer { public static func reduce(_ s: VaultSnapshot, _ c: GTDCommand, env: ReducerEnv) throws(GTDError) -> Reduction }
```

The **reducer is the single place where GTD semantics live** (cap, waiting validation,
completion, promotion, demoting Next actions when their project leaves `active`, archive eligibility…). `extraOps` covers effects on files that are not
snapshot entities (knowledge notes, weekly review note, trash moves).

Derived queries (pure, in `GTDModel/Rules`, owned by T11), e.g.:
`Rules.nextList(snapshot, today:)`, `chaseItems`, `visibleActions` (defer), `stalledProjects`,
`countsTowardCap`, `sidebarCounts`, `dueBadge(for:today:)`, `archiveCandidates`.

### GTDAppCore

```swift
public protocol GTDBackend: Sendable {
  func snapshots() -> AsyncStream<VaultSnapshot>             // emits on every local or remote change
  func perform(_ command: GTDCommand) async throws -> [AppPrompt]
  func undo() async throws                                    // N6: last filing/status change
  func undoLabel() async -> String? }

@MainActor @Observable public final class AppModel {
  public private(set) var snapshot: VaultSnapshot
  public private(set) var undoLabel: String?
  public var prompt: AppPrompt?                               // presented by the app shell
  public let today: () -> Day
  public init(backend: any GTDBackend, today: @escaping () -> Day = Day.today)
  public func send(_ command: GTDCommand) async throws       // rethrows GTDError for the UI to handle
  public func undo() async }

public actor InMemoryBackend: GTDBackend { public init(snapshot: VaultSnapshot) }   // = Reducer only; used by previews, tests
```

Views get the model via `@Environment(AppModel.self)`.

### GTDVault

```swift
public protocol VaultStore: Sendable {
  func snapshots() -> AsyncStream<VaultSnapshot>
  func read(path: String) async throws -> String?
  func commit(_ ops: [VaultFileOp]) async throws -> [VaultFileOp]   // returns the inverse ops (for undo)
}
public final class VaultBookmark { /* pick, persist, resolve security-scoped bookmark */ }
public struct InboxWriter { public func capture(text: String, at: Date) throws -> NoteID }  // usable without loading the vault (C1, T30)
```

`GTDServices.VaultBackend` = `Reducer.reduce` → diff old/new snapshot → encode changed
entities → `VaultStore.commit(ops + extraOps)` → push inverse onto the undo journal.

## 5. UI conventions

- Each feature target exposes 1–3 public root views and nothing else. Public API is listed in its task doc.
- Shared components come from `GTDDesign` (chips, action row, badges, card, and the
  `WaitingInfoSheet` used by inbox, next and waiting views). No dropdowns for
  metadata (I3). An undecided value renders as *empty*, a suggestion renders visibly different
  from a confirmed value (§1).
- Every screen has a `#Preview` backed by `GTDFixtures.sampleSnapshot`.
- Platform split (N5) is decided in the app shell (T40); features use
  `#if os(iOS)` / size classes only for input style (swipe vs keyboard).
- Mac is keyboard-first: every card action has a key equivalent.

## 6. Decisions taken for the open points in REQUIREMENTS §13

| Open point | Decision (changeable, all in one place) |
| --- | --- |
| Swipe mapping | → Next, ← Backlog, ↑ Maybe, ↓ Trash; buttons: Knowledge, Project, Waiting, Defer-to-review. Mac keys: `N B M T K P W R`, `⌘Z` undo. Defined once in `FeatureInbox/CardTargets.swift`. |
| Next at cap during processing | Forced choice sheet: demote one of the current Next items **or** send the card to Backlog. Never automatic. |
| `in-progress` | Counts toward the cap, pinned on top of Next. |
| Routine log format | One markdown file per day per device, entries in frontmatter (see §3). |
| Review stats | Computed on the fly from files (`created`, `completedDate`, log, routine log). Nothing persisted except the `KW` note. |
| Time estimate storage | Minutes; chips write 10 / 30 / 60 / 90; any value > 60 shows as "60+". |

## 7. Sync safety rules (N3) — apply to every task that writes

1. New files are written atomically to a unique name; never append to a shared file.
2. Per-device files carry the device id in the filename.
3. Every read/write of vault files goes through `NSFileCoordinator` (only `GTDVault` touches the file system).
4. Not-yet-downloaded iCloud items are requested with `startDownloadingUbiquitousItem` and reported as `VaultIssue` until available.
5. Conflict copies (`NSFileVersion` unresolved conflicts, "… 2.md" duplicates) are surfaced as `VaultIssue`, never auto-resolved.
6. Tests and agents never touch the real vault. Use `GTDFixtures` or a temp copy.
